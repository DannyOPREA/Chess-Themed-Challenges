# Phase 1, unit 02: Data and content

- Status: In progress
- Log: [logs/phase-1-foundation/02-data-and-content.md](../../logs/phase-1-foundation/02-data-and-content.md)
- Depends on: 1.01 Scaffold

## Goal

The database the game is stored in, the two content sets with a loader that picks one by `CONTENT_SET`, and the phase rules: which phase allows which action, and which phase changes the host can make. The screens in phase 3 build on all three.

## Scope references

- `docs/phases.md`, unit 1.02.
- `docs/scope.md`: "Content" (the test placeholders, Danny's list with its two fixes, `CONTENT_SET`), "Game phases", "Assignment" (assigned at Game on or on joining, never changed), "Player screen" (one active guess per other player, no self-accusation), "Joining and rejoining" (names unique ignoring capitals, 4-digit PIN), "Host page" (remove a player, fix completions).
- `CLAUDE.md` rules 2 (content and game logic stay on the server), 4 (content in the repo, two sets, `CONTENT_SET` starts as `test`) and 5 (the real content stays out of tests, logs and PR text).
- The 1.01 conventions: challenges and decoys are numbered 1 to 20 everywhere, game logic in `src/game/`, content in `src/content/`, tables in `src/db/schema.ts`.

## Work

1. Content, in `src/content/`:
   - `test.json`: "Challenge 1" to "Challenge 20" with "Description of Challenge n" and "Hint for Challenge n", and "Decoy 1" to "Decoy 20" with "Description of Decoy n".
   - `real.json`: Danny's list, converted from `Challenges, Decoys and Hints.txt` in the project's shared files by a throwaway script, with the two fixes (the stray "***" removed from hint 10, "awkardly" corrected to "awkwardly" in hint 14). Each hint is stored on its challenge, since the source pairs them by name.
   - `size.ts`: `CONTENT_SIZE` (20), on its own so the database schema can use it without loading the content files.
   - `index.ts`: `loadContent(contentSet)`, which checks the name is `test` or `real` and the file's shape with Zod (20 challenges each with a name, description and hint, 20 decoys each with a name and description, names unique) and throws otherwise, and `getChallenge` / `getDecoy` to look one up by number. Callers use `loadContent(c.env.CONTENT_SET)`.
2. Phase rules, in `src/game/phases.ts`:
   - `PHASES` in order (`lobby`, `game_on`, `accusations_closed`, `reveal`), their labels, and `phaseSchema` (Zod) for phase names sent in forms.
   - `phaseAllows(phase, action)`: joining in Lobby and Game on; a player marking or undoing their own completion and accusing only in Game on; the host fixing a completion in Game on and Accusations closed; the reveal screen only in Reveal. Rejoining, the host's player list, removing a player, resetting a PIN and "show all" work in every phase.
   - `canChangePhase(from, to)` and `phaseChangesFrom(from)`: each phase moves on to the next, and never back, as `docs/scope.md` describes. The Reveal is final.
3. Player names, in `src/game/names.ts`: `nameKey(name)`, the name in lower case with spaces at either end dropped and repeated spaces collapsed, which is what makes names unique ignoring capitals.
4. The Drizzle schema, in `src/db/schema.ts`, and its migrations:
   - `game`: one row (id 1, enforced) with the current `phase`, which must be one of `PHASES`.
   - `players`: `id` (AUTOINCREMENT, so a removed player's id, and the cookie holding it, never passes to someone else), `name` as typed, `name_key` (unique), `pin_hash` and `pin_salt`, `challenge` and `decoy` (null until assigned, then 1 to 20, both or neither), `completed` (false at first, and only true once assigned), `joined_at`.
   - `accusations`: `accuser_id`, `accused_id` and the accused `challenge` number (1 to 20). The primary key `(accuser_id, accused_id)` gives one active guess per other player (change it by upsert, clear it by deleting the row); a check refuses accusing yourself; both player columns cascade, so removing a player removes the accusations they made and the ones about them; `accused_id` has an index, for "who detected this player".
   - `migrations/0000_init.sql`, generated by `npm run db:generate`; `migrations/0001_seed_game.sql`, a custom migration that adds the game row in the Lobby; and `migrations/0002_assignment_final.sql`, a custom migration with a trigger that refuses changing a player's challenge or decoy once assigned.
   - `getPhase(db)` in `src/db/game.ts`, and the `Db`, `Player` and `Accusation` types.
5. `resolveJsonModule` in `tsconfig.json`, for the content files.
6. `test/reset-db.ts`: `resetDb()`, for `beforeEach` in test files that touch the database, since tests in one file share its database.

## Tests

- `test/content.test.ts`: the tests use the `test` set as `wrangler.jsonc` configures; `loadContent` picks the set named and refuses an unknown name; each set has 20 challenges, each with a non-empty name, description and hint, and 20 decoys, with unique names; the test set is exactly the placeholders, in order; lookup by number, including out-of-range numbers; the real set's hints have no stray asterisks. The real set's text never appears in a test, so the spelling fix was checked when the file was converted instead.
- `test/phases.test.ts`: every action in every phase, every possible phase change, and phase names from forms.
- `test/schema.test.ts`, against the migrated test D1: the game starts in the Lobby, keeps the phase set, has only one row and refuses unknown phases; players start unassigned and not completed, names are unique ignoring capitals and extra spaces, challenge and decoy numbers stay within 1 to 20 and are assigned together, only an assigned player can be completed, an assignment never changes (while other columns still can), a removed player's id is never reused; one accusation per accuser and accused (changed by upsert, cleared by delete), no self-accusation, no out-of-range challenge or unknown player, and removing a player removes the accusations by and about them.

## Done when

- `npm run typecheck` and `npm test` pass, locally and in CI.
- `npm run db:migrate:local` applies the three migrations and the local game row is in the Lobby; `npm run db:generate` then reports no changes.
- Both content sets load and pass their checks.
